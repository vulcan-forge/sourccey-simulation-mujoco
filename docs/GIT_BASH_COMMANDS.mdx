## A) Simulation only

These commands open a simulation window. They do not control the real robot.
Run one at a time.

The ball demo and manual simulator use the arms-down start. Older two-hand,
table-toss, and sorting demos keep their own raised staging poses.

### Ball: reach, grab, lift, and hold

```bash
python -m examples.ball_approach --scene examples/ball_approach.example.json --view
```

Uses a 40 mm ball and simplified contact pads. Opens MuJoCo with both arms
hanging down, raises the active arm beside the table, and performs the pickup.
The window closes automatically afterward. Results are saved to
`artifacts/ball_approach.json`.
Close the window early to stop.

Half-speed arm and gripper motion:

```bash
python -m examples.ball_approach --scene examples/ball_approach.example.json --view --speed 0.5
```

This doubles the duration of movement and closing ramps. Pauses and hold time
stay the same. It slows the actual simulated commands, not just video playback.
Use `--speed 1` for normal speed. Values above 1 are rejected.

### Both hands: grab, lift, hold, and release

```bash
python -m examples.dual_grasp
```

Opens the MuJoCo camera dashboard. Uses contact-only grasping and elevator
motion. Close the dashboard when finished.

### Left arm: reach to a table and toss a block

### Right arm: reach to a table and toss a block

### First real test: follow the path in clear space

The host must be running with both arms connected, VR teleoperation and other
command clients stopped, and the full arm path clear of tables, people, and
objects. This moves the robot through the pickup path and opens/closes its
gripper, without claiming to grasp a real ball.

```bash
cd /c/Users/Theor/Documents/WebsiteCode/VulcanSimulation/SourcceyMuJoCo
source .venv/Scripts/activate
python -m examples.robot_ball_replay --robot-ip 192.168.1.79 --normalized --speed 0.5 --motion-only --execute
```

This opens MuJoCo, returns to the saved arms-down start, slowly opens the left
gripper, and replays the revised motion. The recorded pickup is 20.16 seconds
at normal speed and 40.32 seconds at half speed, plus 4.5 seconds of parked
gripper preparation, return to start if needed, and any feedback pauses. The
offline calculation runs faster than the recorded motion; its wall time is
reported separately. Live playback automatically slows along the same path
whenever the measured arm needs more time. The first
run needs the operator beside the robot. Closing MuJoCo holds the last target;
it does not disable torque.

For double-speed replay with a 5-unit tracking window:

```bash
python -m examples.robot_ball_replay --robot-ip 192.168.1.79 --normalized --speed 2 --tracking-tolerance 5 --motion-only --execute
```

This plans 10.08 seconds of pickup plus 1.125 seconds of gripper preparation,
as a nominal minimum, with return-to-start and feedback pacing separate. The 5-unit window applies
to hold, return, and replay. Errors over 10 units still abort. Motion-only mode
allows a full-range ramped return after a partial replay. Targets advance by
at most 1 unit per command and stay within 5 units of measured positions.
The default `--stall-timeout 15` permits slow movement and aborts if path
progress stops for 15 seconds. The console prints progress during replay.

### Run MuJoCo and the robot together, once preflight passes

Use a physical scene file whose measurements match the actual table and ball,
plus a completed joint mapping. The host must be running with both arms
connected, other command clients stopped, and the return-to-start path clear.

```bash

python -m examples.robot_ball_replay --scene artifacts/ball_approach.physical.json --mapping artifacts/robot_joint_mapping.json --robot-ip 192.168.1.79 --normalized --speed 0.5 --execute
```

This opens MuJoCo, slowly brings the real arms to the verified start, slowly
opens the active gripper, and follows the simulated pickup. Half speed is the
default; feedback pauses may extend it. The window shows mapped real arm
feedback. The ball is a scene marker, not a measured real object.

If preflight fails, **no commands are sent**. A tracking stall aborts. Closing
MuJoCo holds the last command; it does not release torque or act as an emergency
stop. Feedback and targets are saved in `artifacts/robot_ball_replay.jsonl`.
